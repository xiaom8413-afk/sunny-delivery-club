# 架构与实现说明

本文对应 1.2.0，描述仓库实际实现。项目使用原生 HTML、CSS、JavaScript 和 Canvas 2D；游戏运行时没有第三方依赖，也没有远程服务。

![架构与数据流](images/architecture.png)

## 一、职责边界

| 文件 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| `index.html` | 页面结构、按钮、设置和结算面板 | 战斗判定 |
| `style.css` | 纸感配色、布局、按钮和小屏适配 | 游戏物理 |
| `engine.js` | `Game` 状态、敌人、关卡、寻路、碰撞、技能、分数和检查点 | DOM、音频、网络 |
| `game.js` | 键鼠输入、主循环、绘图、HUD、事件音效和本地存储 | 重新实现一套战斗规则 |
| `build.cjs` | 将样式和脚本内联到一个 HTML | 压缩、转译或资源下载 |
| `server.cjs` | 可选的本机静态文件服务 | 登录、游戏数据或在线 API |

`engine.js` 既能通过 CommonJS 在 Node 中加载，也能在浏览器中提供 `window.Sunny`。界面层创建 `Game`，传入输入，再消费 `game.events`。例如伤害判定先产生 `hurt` 事件，界面据此绘制文字和播放提示音；音效关闭不会改变战斗结果。

状态主要是 `menu → playing → upgrade → playing`，并有 `paused`、`dead`、`won` 分支。练习区复用同一引擎，以 `practice` 标记免伤、补充靶机并禁止正常通关和正式存档。

## 二、固定步进与输入

世界逻辑尺寸为 **1200 × 760**。界面通过 `requestAnimationFrame` 渲染，将真实时间放入累加器，以 **1/60 秒**推进引擎。每个渲染帧最多执行 6 次模拟，并将单帧时间差限制为 0.1 秒，避免长时间卡顿后无限追赶。

移动输入先归一化，防止同时按两个方向时斜走更快。玩家和敌人的移动按 X、Y 轴分别解决与矩形障碍的碰撞。冲刺仍走同一套碰撞逻辑，不能穿过纸箱墙。

页面失去焦点或切到后台时会清理按键、释放射击并暂停。设置对话框打开时也会暂停，避免修改偏好期间持续受到伤害。

画布按可用大小缩放，设备像素比最多取 2。鼠标坐标会从页面坐标转换到固定世界坐标；CSS 响应式布局与世界物理尺寸相互独立。

## 三、地图与 BFS 流场

地图使用 **40 像素格子、30 列 × 19 行**。每站有一份手工编排的障碍计划，并使用种子在部分横向位置上做小幅变化。中央派件区会被预留。

生成器准备两份占据网格：

- 普通网格表示被箱子或边界占据的格子。
- 大型网格额外考虑半径 31 的通行宽度，为较大的首领保留空间。

从玩家所在格开始向外进行 BFS，记录各格到玩家的距离。地图生成后检查普通和大型网格的可达性；如果存在孤立的可行走区域，会逐步移除末尾装饰障碍直到检查通过。

运行时约每 **0.18 秒**更新流场。敌人能直接看到玩家时直接接近；被障碍阻挡时，沿相邻格中距离更小的方向移动。体型半径大于 20 的敌人使用大型流场，局部分离力减少敌人叠成一点。

这里使用的是**共享 BFS 距离场**，不是为每个敌人逐帧单独运行 A*。可重现的是同一种子、同一站点的地图；若玩家输入和时间步不同，战斗过程也会不同。

## 四、子弹如何命中

每个模拟步计算子弹从当前位置到下一位置的线段，而不是只检查终点是否落在目标内部：

1. `segmentBox` 求线段与障碍矩形的首次交点，矩形按子弹半径向外扩张。
2. `segmentCircle` 求线段与目标圆的交点。
3. 先比较障碍与目标交点的距离，仅保留墙壁前方的目标。
4. 多个目标按交点排序，依据穿透次数逐个处理。

这样能减少高速弹丸穿过薄墙、跳过近处目标，或者先打到墙后敌人的问题。已经命中的敌人 ID 保存在子弹集合里，避免同一发弹重复伤害同一目标。

这是针对当前对象尺寸与规则的连续弹道检测，不是通用刚体物理引擎；运动机体本身采用固定步长下的轴向碰撞处理。

## 五、分身与退件

### 时间分身：回放，而不是自动规划

每步记录 `{ x, y, angle, fired, damage }`，最多保留 **240 帧**。在 60 Hz 下，对应最近最多 **4 秒**。按 `E` 时复制这段历史并建立回放游标；后续每步按顺序读取，设置分身的位置和朝向，在记录为开火的帧重新发射子弹。

基础分身伤害系数为 0.75，可通过改装提高。第 7 站建立两个回放实例，第二个延迟 0.5 秒。分身不自主寻找新路线，也不会预测玩家意图。

![时间分身的数据记录与回放](images/replay-diagram.png)

### 退件：转换阵营，再追踪可见目标

按 `Q` 时，范围内敌方子弹会改为友方、标记为纸飞机、重置伤害与寿命，并先反转速度。后续寻找最近的可见敌人，逐步朝目标速度转向；视线检查和墙壁碰撞仍然存在。

因此它不会隔墙必中，也不会凭空生成整屏弹药。转化多少纸飞机，取决于发动瞬间范围内实际存在多少敌弹。技能还会伤害、击退附近敌人，并给予短暂无敌。

## 六、派件、检查点和偏好

派件状态为 `waiting → carrying → done`。玩家接近包裹 36 像素以内自动取件，回到中央投递点 65 像素范围内累积签收进度，约 0.65 秒完成。离开时进度缓慢回退；完成后只能领取一次奖励。

正式检查点记录的是**进站状态**：种子、站点、装备、分数、击毁数、时间、派件数和模式。恢复时重新应用合法改装并重新生成本站地图。存档不保存半途飞行的子弹、敌人位置或未完成的包裹；失败重试也不会让同一包裹奖励反复累积。

浏览器存储键：

| 键 | 内容 |
| --- | --- |
| `sunny-delivery-run` | 当前派送的站点检查点 |
| `sunny-delivery-prefs` | 难度、辅助瞄准、柔和动效、音量等偏好 |
| `sunny-delivery-best` | 本浏览器最高分 |

加载存档会验证版本、站点、数值范围、改装 ID 与次数。存储读写失败会被捕获，游戏仍可运行。没有云同步，存储也不提供作弊防护。

## 七、绘图、音效与对象上限

机甲、履带、纸飞机、邮筒、包裹和场景装饰由 Canvas 图形函数绘制；音效由 Web Audio 的振荡器与增益包络合成。界面层有自己的粒子、圆环和浮动文字，不写入正式战斗规则。

当前主要保护边界包括：敌人最多 40、子弹最多 320、回放历史最多 240 帧、单次事件队列最多 250、粒子最多 420、浮动文字最多 30。常规出场另受悠闲模式 9 台 / 标准模式 14 台的密度限制；首领召援有独立条件。

这些上限用于控制当前实现的最坏情况，并不等于所有低配置设备都经过性能验证。

## 八、打包与扩展建议

`build.cjs` 读取四个固定源文件，将 CSS、引擎与界面脚本内联到 `index.html`，生成独立 HTML。不依赖远程字体、图片、CDN 或包管理下载。持续集成会在重新打包后检查产物与已提交文件是否一致。

扩展时可沿现有边界进行：

- 新关卡规则放在引擎层，同时补上对应的行为测试。
- 新视觉主题优先放在绘图层，保持碰撞和寻路规则独立。
- 新存档字段需要明确缺省值、合法范围与旧版本处理方式。
- 修改地图或机体尺寸后，重新验证两种体型的可达性。
- 修改来源文件后重新打包，确保双击版本与源码入口一致。

更多验证边界见 [测试说明](testing.md)。
