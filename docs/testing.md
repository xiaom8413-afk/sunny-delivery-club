# 测试与验证边界

当前源码版本：**1.2.0**。2026-09-24 对发布副本执行 `npm test`，结果 **20 项通过、0 项失败**；重新构建的独立 HTML 与原项目打包产物逐字节一致。

## 运行

安装 Node.js 22 或更新版本后，在仓库根目录执行：

```sh
npm test
npm run build
```

测试使用 Node.js 自带的 `node:test` 和 `node:assert/strict`，无第三方依赖，不需要 `npm install`。`npm test` 当前包含 **20 项**测试；它直接加载纯逻辑引擎，不启动浏览器。

打包后可检查是否有未同步的产物：

```sh
git diff --exit-code -- 晴空派送局.html
```

如果本次修改了源代码，打包产物产生差异是正常的，应一起审查并提交。持续集成对已提交内容执行同一流程，确保仓库里的单文件游戏与源代码一致。

## 两种“通关测试”要区分

测试 8 会直接清空当前敌人和生成队列，用于快速验证状态转换与三选一逻辑。它不代表完成了战斗。

测试 12 保留真实敌人生成、弹道、伤害、首领和改装过程，由固定的测试驾驶员瞄准可见敌人。**测试驾驶员被赋予无敌状态**，因此可以稳定检查战斗流程是否最终结束。

该测试能发现生成队列丢失、首领无法结束、升级后无法进入下一站等问题，不能证明普通玩家在正常电量下容易通关，也不是平衡性、娱乐性或人类操作水平的评测。

## 持续集成

[`.github/workflows/test.yml`](../.github/workflows/test.yml) 在 push 和 pull request 时使用 Node.js 22 执行：

1. 20 项逻辑测试。
2. 独立 HTML 构建。
3. 构建产物与提交版本的差异检查。

工作流只申请仓库内容读取权限，不自动发布，不上传测试场景截图，也不运行浏览器自动化。

## 建议的手动检查

发布或改动界面后，仍应在真实桌面浏览器中检查：

- 双击独立 HTML 能打开；源码入口与打包版本行为一致。
- 首页、试驾、开始游戏、暂停、返回首页、设置和重试都可使用。
- WASD、鼠标、自动开火、分身、退件和冲刺有清晰反馈。
- 开启和关闭声音、柔和动效、辅助瞄准后没有明显异常。
- 正式派件可以取件、签收，清场后可选择改装。
- 重新加载后从本站起点继续，试驾不覆盖正式进度。
- 浏览器窗口缩放后，按钮不遮挡关键信息，瞄准坐标仍正确。
- 切到其他页面后自动暂停，不因键盘焦点丢失持续移动或开火。

## 当前没有宣称的保证

这些测试不是全设备兼容认证，也未覆盖所有随机种子、所有升级组合或玩家习惯。当前版本没有云存档、账号系统、联机同步、完整手机触控或游戏手柄支持。

已有界面图片来自此前浏览器功能验证，其中取件与签收使用预设测试状态；此次后期关卡图片是复用源码绘图逻辑离线绘制的场景示意。它们用于解释机制与关卡，不应视为普通玩家的自然通关成绩。

原开发项目曾使用无界面 Chrome 脚本进行界面交互与截图验证；本发布副本没有包含该开发用截图脚本，CI 也不运行它。20 项通过只指本次运行的逻辑测试，不应解读为所有界面交互都重新自动验收。若发现问题，请在 Issue 中附上浏览器版本、站点、模式、操作步骤与必要截图；不要上传个人敏感信息或整个浏览器资料目录。
